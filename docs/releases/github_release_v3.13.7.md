# v3.13.7 — 元数据工具：拍摄时间显示语义修复 + GPS 复用信息完整性

## 一、拍摄时间"设定值与标签不一致"的定位与修复

**定位结论**：v3.13.4 修复后，写入链路本身已是时刻精确的（naive/UTC Z 两种设定形态实测均精确还原，见 `docs/ACCEPTANCE_metadata_v3.13.2.md` 第七节）。残留的不一致来自**显示层**：源信息面板展示拍摄时间时剥掉 `Z` 后直接把 UTC 墙钟当本地时间显示（如源标签 12:12:41Z 显示为"12:12:41"），用户按显示值设定时间，写入按本地语义解释，产出标签即相差 ±8 小时。

**修复**：源信息面板的拍摄时间显示统一走 `utcToLocalNaive()` 转换——**显示（本地墙钟）= 复用填充值 = 写入语义**，三处一致。另需说明：MP4 的 creation_time 标签存储的是时刻（UTC 秒），不同工具按各自时区显示，本工具保证"显示值 = 设定值 = 标签时刻的本地表示"。

**实测**：naive 设定 15:30 → 标签 07:30Z（本地 15:30）、FS 创建/修改时间 15:30:00；UTC Z 设定 12:12:41Z → 标签回读 12:12:41Z（瞬间精确还原）、FS 时间 20:12:41（该瞬间本地墙钟）。

## 二、复用 GPS 位置信息完整性

**定位结论**：两层缺陷——① `probe-source`/`probe_metadata` 读取地名只认 `location.name/location_name` 键，而本工具 v3.13.3 起地名写入 `description`；地址（comment）在 probe-source 中完全未读取、响应也无 `location_address` 字段——本工具自己处理过的文件反而读不回地名/地址；② 复用逻辑只照抄探测值，源文件只有坐标（相机普遍不写地名/地址文本）时无补全手段。

**修复**：
- 后端：两个探测端点的地名读取链加入 `description` 回退；`probe_source` 新增地址读取（comment）并在响应中返回 `location_address`；
- 前端：「复用 GPS 位置」改为异步补全——坐标立即填充，地名/地址缺失时调用逆地理（与地图选点同一套 AMap regeo + Nominatim + 兜底解析，已抽取为共用的 `resolveReverseGeo()`，消除重复实现）补全文本。

**实测（全链闭环）**：写入 GPS+地名+地址 → probe-source 读回坐标/地名/地址三项全对 → 复用按钮完整填充三字段（含纯坐标源的逆地理补全）。
