# 360VideoConverter v3.10.0 发布说明

发布日期：2026-08-24

## 新特性

### 1. 8K / 6K 高分辨率输出支持
- 分辨率预设新增：**7680x3840 (8K 全景)**、**5760x2880 (6K 全景)**
- Okaa 双鱼眼校正输出分辨率同步支持 6K/8K
- 适配 Insta360 X4 原生 8K 素材的完整转码链路

### 2. 自定义分辨率输入
- 分辨率下拉新增「自定义分辨率…」选项，可输入任意 `宽x高`（如 6400x3200）
- 前端校验：格式合法性 + 宽高必须为偶数（yuv420p 要求）
- 预设保存/加载正确回填自定义值（不在预设列表时自动切换到自定义模式）

### 3. Level 编码级别修复与扩展
- **修复死参数 Bug**：`level` 此前从未传给 ffmpeg，现在软编码器（libx264/libx265）真正应用 `-level:v`
- Level 下拉新增 **6.0 (6K/8K 全景)**、**6.1 (8K UHD)**、**6.2 (8K+ 超大帧)** 选项
- **Level 自动提升**：选择 6K/8K/超规格自定义分辨率时，自动提升至最低合规 Level（6K/8K → 6.0）
- 硬件编码器（NVENC/QSV/AMF）保持 Level 自动选择（其 `-level` 为整数枚举，不适合直接透传）

### 4. 高分辨率编码器智能门控
- H.264 硬件编码（NVENC/QSV/AMF）上限为 4096x4096 → 选择 >4K 分辨率时**自动切换至对应 HEVC 编码器**（前端 + 后端双重保障）
- 超出 H.264/HEVC Level 表最大帧尺寸（>71.3M 像素，如 16K）时输出非标 Level 警告

### 5. 码率自适应建议
- 选择 6K/8K 分辨率时，若最大码率仍为 4K 默认值 40M，**自动调整为 80M (6K) / 120M (8K)**
- 后端在 6K+ 分辨率 + maxrate < 60M 时输出块效应风险提示日志

## 技术细节

### Level 合规判定表（H.264/HEVC MaxFS/MaxLumaPS 保守并集）
| Level | 最大帧像素 | 覆盖分辨率 |
|-------|-----------|-----------|
| 5.1 | 8,912,896 | 4K 全景 (4096x2048)、4K UHD |
| 6.0 | 35,651,584 | 6K 全景、8K 全景 (7680x3840) |
| 6.1 | 71,303,168 | 8K UHD (7680x4320) 及以下 |
| 超表 | — | 16K 等超规格（非标，警告） |

### 实测验证（本机 ffmpeg-static）
- libx265 8K (7680x3840) + `-level:v 6.0`：✅ 编码成功，输出 level=180 (6.0)
- libx264 8K：✅ 成功
- 16K (15360x7680)：⚠️ 软编可编码但 Level 超表（非标值），仅限极客自定义使用

### 已知边界
- 8K 软编码速度极慢（x265 ultrafast 约 1.5fps 实测），强烈建议使用硬件 HEVC 编码
- YouTube 上限 8K；VR 头显单眼面板最高约 4K，8K 全景主要用于高清投屏和后期裁切
- VR 3D 合成中分辨率为合成后整帧分辨率（非单眼），8K TB/SBS 均在 Level 6.0 合规范围内

## 完整变更
- `app.py`：新增 `enforce_hires_compat()` / `min_level_for_pixels()`；`build_cmd()` 与 `build_vr3d_cmd()` 传入 `-level:v`；`convert_one()` / `vr3d_merge_one()` 编码前执行高分辨率兼容性调整
- `static/index.html`：分辨率/Level/Okaa 分辨率下拉扩展；`onResolutionChange()` 联动（Level 提升 + 编码器切换 + 码率建议）；`collectParams()` 自定义分辨率校验；`applyParams()` 自定义值回填
