## 一、修复：GPU 利用率永远显示 N/A（v3.13.1）

**现象**：装有 NVIDIA GeForce 显卡（如 RTX 3090）的机器上，系统资源面板的 GPU 利用率永远显示 N/A，但 GPU 名称能正常识别。

**根因**：nvidia-smi 的 `utilization.memory` 指标**仅在 Quadro/Tesla 上支持，GeForce（消费卡）返回 `"[N/A]"`**。旧实现用裸 `int()` 解析全部字段且无容错——一个 `"[N/A]"` 就让整个采样抛异常，导致没有任何 GPU 数据，且每秒采样都重复失败。

**修复**：
1. 查询中移除 GeForce 不支持的 `utilization.memory`；显存占用率改为 `memory.used / memory.total` 计算（所有卡都支持）
2. 解析改为**逐字段容错**：单个字段 `[N/A]` 只跳过该字段，不再拖垮整个采样
3. **打包环境内置 pynvml**（库调用，无子进程开销）——装有 NVIDIA 驱动的机器直接走主路径，数据更全（含编码器占用率）；无驱动的机器自动回退

配套 9 项单元测试（模拟 GeForce `[N/A]`、全 `[N/A]`、正常、非零返回码、字段不足五种 nvidia-smi 输出）全部通过。

## 二、修复：频繁弹出未知窗口的闪烁（v3.13.0）

**现象**：界面频繁闪烁，观感如同不断弹出未知窗口，影响正常使用。

**排查**（四步取证）：前端弹窗原语挂钩计数 15 秒全部为 0 → 排除前端高频弹窗；后端 subprocess 审计发现 `sysmon.py` 的 GPU 采样缺 `CREATE_NO_WINDOW`（在装有 nvidia-smi 的机器上会**每秒闪一个控制台窗口**，已修复）；最后用 Win32 `EnumWindows` 以 200ms 间隔采样主窗口出现后的 20 秒（99 次采样），**本进程零新窗口** → 确认闪烁不是真实窗口，而是渲染层问题。

**根因**：三栏工作台引入的两处 `position: sticky` + `box-shadow` 合成层，在**无 GPU 直通环境（VMware 虚拟机 / RDP 远程桌面）**里，Chromium 的 DirectComposition 合成路径会频繁闪烁。

**修复**：
1. `sysmon.py` 补齐 3 处 `CREATE_NO_WINDOW`
2. WebView2 默认禁用 GPU 加速、改走 CPU 合成（本应用是表单/表格型界面，无重绘负载）。**如需恢复 GPU 加速**：设置环境变量 `360VC_ENABLE_GPU=1` 后启动
3. 滚动容器加 `scrollbar-gutter: stable`，消除滚动条出现/消失引起的布局抖动

## 三、新增：编码 copy 模式（流复制）

编码参数面板顶部新增开关「**直接复制源流（-c copy，不重编码）**」：

- **用途**：只改封装与元数据（GSpherical 注入、faststart、拍摄时间、GPS），不做任何重编码——**零画质损失，速度接近磁盘拷贝**
- **生成的命令**：`-map 0 -c copy`，不含任何滤镜或编码器参数，但**保留全部元数据写入**
- **互斥保护**：`-c copy` 不能与任何视频滤镜共存（滤镜必须重编码）。启用后前端把 5 个「必须重编码」的参数组置为惰性（半透明、不可交互）、编码器下拉禁用并显示提示框；后端再兜底一次强制忽略 okaa / Insta360 拼接 / vidstab / 缩放，**双保险**
- **批量任务逐任务设置**：copy 开关随参数快照写入每个任务，可在批量模式里对单个任务单独开关

## 四、元数据读取功能增强（4 项）

### 1. moov atom 支持标注

每个媒体条目新增徽章，明确标注 moov 状态与位置：

| 徽章 | 含义 |
|------|------|
| `moov ✓ 前置`（绿） | moov 在文件头部（faststart），适合网络流播 |
| `moov ✓ 尾部`（黄） | moov 在文件尾部（录制未做 faststart） |
| `moov ✗ 缺失`（红） | 无 moov → 文件不完整或已损坏 |

实现是**纯 Python 的 MP4 box 解析**：只读每个 box 的头字节并 seek 跳过内容，**绝不整读文件**（视频可能几十 GB）；防御损坏文件导致的死循环。配套 **12 项单元测试**全部通过。

### 2. 批量结果筛选（按源数据功能分类）

筛选栏：**一个字段下拉（`<optgroup>` 按六类源数据功能分组，共 18 个字段）+ 关键词输入**。分类：容器（moov/封装/大小/时长）、视频流（编码器/分辨率/帧率/码率/pix_fmt）、音频流（编码/采样率/声道）、球面元数据（GSpherical/pano 类型/立体模式）、时间（creation_time）、位置 GPS（经纬度/名称/地址）。

- 关键词「包含」语义、大小写不敏感；moov / GSpherical 布尔字段自动切换「全部/是/否」三态
- **纯前端过滤**即时重渲染，显示「筛选后 X / 共 Y 个」

### 3. 批量结果多选 + 全选 / 反选 / 清空

- 每个条目带复选框，工具栏提供**全选 / 反选 / 清空**
- **关键语义**：全选/反选只作用于**当前筛选可见**的条目；勾选状态**按文件路径记录**（而非显示索引），**筛选条件变化不会丢失已勾选项**
- 实时显示「已选 N 个」

### 4. 选中的媒体加入批量转换队列

- 「加入批量转换队列（已选 N）」：把选中文件按现有任务结构加入批量队列，**每个任务携带独立的参数快照**，随后**自动切换到批量转换模式**，可在批量模式里对单个任务单独调整参数
- 边界：未勾选时用轻提示（不弹原生对话框）；重复文件自动跳过并提示跳过数量

## 六、已知限制

- **CSS 视觉效果无法自动化验证**（本环境无可用无头浏览器），观感以人工确认为准
- `location_name` / `location_address` 筛选字段对大多数文件筛不出结果（报告数据来自 ffprobe tags，通常只有原始 GPS 串；名称/地址由注入流程另存）
- 静态 DOM 上仍有 118 处存量内联事件未迁移（本次未新增任何内联事件），后续按同一分发器模式分批迁移
- 「禁用 GPU」是针对虚拟机/远程桌面环境的稳妥解；若在物理 GPU 机器上发现滚动流畅度下降，可设 `360VC_ENABLE_GPU=1` 对比
