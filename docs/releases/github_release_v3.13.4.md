# v3.13.4 — 元数据工具「复用」链路修复：弹窗复用入口 / 拍摄地点兜底 / 文件名日期互斥 / 时间写入 ±8h 漂移

针对元数据工具批量流程实测发现的 4 个缺陷的专项修复（复现、修复与验证全过程见 `docs/ACCEPTANCE_metadata_v3.13.2.md` 与 `scripts/frontend-gate/_verify_meta_reuse_flows.js`）。

## 一、批量编辑弹窗新增「复用」入口（此前复用只在全局面板）

- 编辑弹窗新增「复用素材 GPS 及地名 / 复用拍摄时间」按钮，数据来源 = 该文件自身的探测结果；
- 复用回填扩展到**详细地址**；地名缺失时用地址首段兜底，拍摄地点始终有内容；
- 弹窗内支持地图选点（与全局面板同一条选点链路）。

## 二、拍摄地点显示修复

- 地图直接点击且逆地理无 POI 时，地点名此前落为坐标串或空——现从地址首段推导兜底；
- 批量队列 GPS 徽章新增**地名**显示（此前只有坐标）。

## 三、文件名日期真实生效

- 加入队列时自动探测会把源拍摄时间写入「手动指定日期」，此后勾选「从文件名提取日期」不清空它，后端优先级（手动＞文件名）导致文件名日期永远不生效；
- 现勾选「从文件名提取日期」即清空手动指定框（两来源互斥），用户选择的日期来源真实下传。

## 四、时间写入 ±8 小时漂移修复

- 自动探测返回的拍摄时间是 **UTC（带 Z 后缀）**，旧链路原样写入手动日期：文件属性中的创建/修改时间与元数据标签**互相相差 16 小时、且都与设定值不符**；
- 修复：前端在进入设置前将 UTC 归一化为本地时间；后端对带时区的输入统一 `astimezone` 转本地再写（转换与元数据两条链路同步加固）；
- 实测：以 `2026-05-26T12:12:41Z` 设定 → 产物标签回读 `2026-05-26T12:12:41Z`（瞬间精确还原）、文件属性创建/修改时间 = 本地 20:12:41。

## 五、验证

- jsdom 真实页面四场景验证 17/17（`scripts/frontend-gate/_verify_meta_reuse_flows.js` 入库）；
- 打包 exe 端到端 3 项 PASS（UTC 回读精确 / 文件名日期生效 / 原有 naive 语义回归不变）；
- 回归门禁 01–09 全绿（07 36/36、08 12/12）。
