# v3.12.1 — 修复「新版 UI 未生效」

## 问题现象

安装 v3.12.0 后打开程序，界面与旧版**完全一致**，看不到三栏工作台、手风琴折叠等新布局；控制台无报错、无失败请求，极易误判为「改动没生效」。

## 根因

**三栏工作台被自身的响应式断点压回了单列，而且是启动瞬间就发生的。**

两侧配置互相冲突：

| 位置 | 配置 |
|------|------|
| `static/css/app.css` | `@media (max-width: 1280px) { .workspace { grid-template-columns: 1fr; } }` |
| `app.py` | `webview.create_window(..., width=1280, height=860)` |

应用窗口宽度恰为 **1280px**，减去滚动条后视口 ≤1280px，**媒体查询条件立即命中**，`.workspace` 被改为单列。而单列下的元素顺序（标题栏 → 模式标签 → 编码面板 → 业务面板 → 操作栏 → 系统资源 → 日志）与旧版布局几乎完全一致，因此观感上「没有任何变化」。

唯一残留的可见差异（手风琴箭头、2 个默认折叠的分组）因为样式刻意沿用了原 `.section-divider` 的字号/字重/大小写/颜色，非常不显眼，容易被忽略。

### 为什么此前的验证没有发现

- 静态检查（语法、id 契约、`data-action` 契约）与 DOM 结构检查（手风琴 9 组、`.ws-col` ×3）都**只验证了 DOM 是否存在**，不涉及 CSS 媒体查询是否命中
- jsdom 不实现 CSS 布局与媒体查询，因此「真实 DOM 验证」也测不到
- 无头浏览器在本环境无法产出输出，没有可用的视觉回归手段

**教训：响应式断点与应用窗口宽度是一组必须联校的配置，单看任何一侧都发现不了冲突。**

## 修复

1. **降低单列回落断点**：`1280px → 1100px`（`app.css`），并收窄两侧栏（左 `minmax(260px,300px)`、右 `minmax(240px,290px)`），为中间工作区让出更多宽度
2. **加宽默认窗口**：`1280×860 → 1440×900`，`min_size` 由 `(900,600) → (1024,640)`（`app.py`），使三栏布局有足够的展示空间
3. **界面资源禁用缓存**（`app.py` 新增 `after_request`）：对非 `/api/` 路径统一下发 `Cache-Control: no-store`。原版本各版共用同一 URL（`http://127.0.0.1:<port>/`）且 Flask 对静态文件只发 `Last-Modified`/`ETag` 不发 `Cache-Control`，WebView2 可能套用启发式新鲜度而**直接复用上一版本缓存的 `index.html`** —— 那同样会表现为「装了新版但界面不变」且毫无报错。本地单机应用资源极小，禁用缓存代价可忽略，换来「安装即生效」的确定性
4. **新增回归门禁 `09-layout-breakpoint.js`**：自动校验「应用默认窗口宽度 > 单列回落断点 + 100px 余量」，并把该项固化为每次改动都必须通过的检查

## 若安装后仍显示旧界面

按顺序排查（均已验证过核心版本，以下为兜底）：

1. 确认启动的是 `C:\Program Files\360video-converter\360VideoConverter.exe`，且其修改时间为本次安装时间
2. 确认窗口标题栏右侧版本号显示 **v3.12.1**（程序内置 `/api/version` 会回显）
3. 若仍异常，删除 WebView2 用户数据目录后重启（缓存兜底）：
   `%LOCALAPPDATA%\Temp\tmp*\EBWebView`
4. 窗口宽度需 ≥1100px 才会呈现三栏；若被手动缩窄，请拉宽或使用「最大化」
