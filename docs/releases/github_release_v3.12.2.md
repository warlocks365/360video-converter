# v3.12.2 — 前端架构重构（模块化 / 工作台布局 / 事件委托）

> **纯前端架构重构，不新增也不删减任何功能。** 所有转换模式、参数项与交互能力保持完整；后端 `app.py` 除缓存策略与窗口尺寸外未改动。
>
> 本说明覆盖自 **v3.10.0** 起的全部变化（v3.11.0 / v3.12.0 / v3.12.1 为过程版本，未单独发布）。

---

## 一、架构：单文件 → 模块化

改造前前端是单个 `static/index.html`（**6096 行**，含 4290 行内联 JS + 579 行内联 CSS），无法并行维护。现已按职责拆分：

| 文件 | 行数 | 职责 |
|------|------|------|
| `static/index.html` | 1295 | 纯 DOM 骨架（零内联 JS/CSS） |
| `static/css/app.css` | 700 | 全部样式 |
| `static/js/00-core.js` | 273 | 状态 / 工具 / 统一轻提示 / 空值安全 DOM 辅助 / **事件委托分发器** |
| `static/js/10-ui.js` | 609 | 模式切换 / 折叠开关 / 弹窗 / tooltip / 原生对话框 / 路径字段工厂 |
| `static/js/20-map.js` | 525 | 地图与坐标（Leaflet / GCJ-02 转换 / 地理编码） |
| `static/js/30-params.js` | 438 | 参数采集回填 / 预设 / 分辨率与码率联动 |
| `static/js/40-files.js` | 682 | 目录扫描 / 任务表 / 合并表 / 任务持久化 |
| `static/js/50-meta.js` | 645 | 元数据工具 / 三套设置区统一采集回填 |
| `static/js/60-jobs.js` | 852 | 任务调度（控制器 / 轮询 / 渲染器） |
| `static/js/70-report.js` | 293 | 元数据报告 |
| `static/js/80-codec.js` | 375 | 编码器检测 / 诊断 / 日志导出 |
| `static/js/90-boot.js` | 51 | 启动初始化 |

拆分采用**脚本驱动的顶层语句整块切分**（函数绝不被截断），并内置 4 项无损校验：块索引分区完整、块区间连续无重叠、按块索引拼回与原脚本**逐字符一致**、写盘后逐模块重解析块集完全匹配。

> 模块加载顺序由文件名数字前缀决定，`90-boot.js` 的 `init()` 必须最后执行。

## 二、布局：三栏工作台

- `.app` 最大宽度 1200 → **1920px**
- 主体改为三栏：**左＝参数配置｜中＝工作区｜右＝实时监控**（右侧 sticky，不随主内容滚走）
- 操作栏移至工作台之后并 `position: sticky; bottom: 0` **吸底常驻**
- 默认窗口 **1440×900**（原 1280×860），`min_size` 1024×640
- 窄屏（≤1180px）自动回落单列

**效果**：1920px 屏横向空间利用率约 63% → **约 90%**；「开始转换」距首屏约 2500px → **0**（无需滚动即可触达）。

### 侧栏内容适配

参数配置面板原按约 1160px 全宽设计（内含 10 处四列字段网格），放进侧栏后每列仅约 57px，标签会被压到 min-content 而**逐字折行**。侧栏语境内做了针对性适配：四列网格降为两列、两列降为单列、网格项与表单控件显式 `min-width: 0`（否则 `<select>` 会按最长选项撑破网格）、卡片内边距收紧。**字段宽度由约 57px 提升到约 181px。** 右栏系统资源由 5 列降为 2 列（每格约 40px → 110px）。

各断点下的列宽：

| 视口宽度 | 左栏 | 中间工作区 | 右栏 |
|---------|------|-----------|------|
| 1900（1080p 最大化） | 400px | 约 1158px | 270px |
| 1440（默认窗口） | 400px | 约 698px | 270px |
| 1280 | 360px | 约 608px | 240px |
| ≤1180 | 单列回落 | — | — |

## 三、编码参数手风琴

`#encodeParams` 内 9 个分组全部包装为可独立折叠的分组，**默认仅折叠 2 个设备专项分组**（Okaa 双鱼眼校正、Insta360 原生文件处理）——这两个分组只在使用对应设备拍摄时才有意义，且均为 opt-in 功能。其余 7 组保持展开，不改变既有操作习惯。

折叠使用 CSS `display:none`，**控件始终留在 DOM 中**，因此折叠状态下的参数照常参与采集，不会丢失。

## 四、事件委托（消除 XSS 攻击面）

动态生成 HTML 中的内联事件全部迁移到「`data-action` + 中央事件委托」：

| 指标 | 改造前 | 改造后 |
|------|-------|-------|
| 动态生成区域的内联事件 | 20 处 | **0** |
| `javascript:` 伪协议链接 | 1 处 | **0** |
| 全局内联事件总数 | 148 处 | **117 处** |

**为什么这能消除 XSS 面**：`esc()` 在「JS 写在 HTML 属性里」这种上下文中并**不充分**——HTML 实体先于 JS 解码生效，`&#39;` 在 JS 解析时已还原为引号，仍可闭合字符串。改成 `data-*` 属性后，属性里不再出现函数名与引号嵌套结构，该攻击面自然消失。顺带修正了编码器警告中未转义的 `codec` 参数。

分发器有三处关键设计：**绑定在 `document` 而非业务容器**（编码器状态区被 5 个函数轮流整体重建，绑容器上会丢监听）；表单控件只响应 `change`、其余只响应 `click`（防双触发）；未注册的 action 显式报错而非静默失效。

## 五、任务调度重构（消除任务状态串台）

改造前 `jobId` / `pollTimer` 是裸全局单例，且「开始转换」与「应用元数据」两个入口**各自只禁用自己那个按钮**——元数据任务运行期间点「开始转换」会覆盖 `jobId`，导致前一任务的轮询被夺走、**进度永久冻结**。

现已改为显式控制器：`ActiveJob`（`beginJob` / `endJob`），检测到已有任务运行时**明确拒绝并提示**；两个主按钮**同时禁用/启用**；单一轮询器按任务类型分派渲染器。同时删除了 274 行死代码（`pollStatus` 曾被二次覆盖赋值，原实现不可达）。

## 六、其他改进

- **单一操作栏**：元数据专属操作栏与共享操作栏结构完全相同、仅 id 前缀不同，造成 10 个进度 DOM 元素重复。已合并为单一操作栏；主操作按钮配色统一
- **元数据设置区逻辑统一**：三套设置区（转换面板 / 元数据工具 / 单行编辑弹窗）的采集与回填收敛为一份参数化实现
- **路径输入统一**：14 处「输入框 + 浏览按钮」的硬编码调用统一为 `data-action` + `data-path-*` 描述目标
- **轻提示统一**：原 4 套独立实现（z-index 分别为 9999/99999/100000/100001、停留时长 2500/4000/8000ms）统一为 1 套，按时长语义分档
- **界面资源禁用缓存**：各版本共用同一 URL，若不禁止，浏览器启发式缓存可能复用上版 `index.html`，表现为「装了新版但界面不变」且无任何报错
- 消除重复实现：增量日志渲染、按钮复位、日期预览、球面模式拆分、编码器提示气泡
- CSS 变量收口 40 处硬编码颜色

### 修复的既有缺陷

| 缺陷 | 位置 | 现象 |
|------|------|------|
| `lon` 未定义 | `20-map.js` | 地图点击选点后逆地理编码抛 `ReferenceError` 而失败（改造前既有） |
| VR3D 任务无暂停按钮 | `startVR3D` | 该函数缺失按钮复位逻辑（另两个入口各有） |
| `m_` 侧采集逻辑重复 | `50-meta.js` + `60-jobs.js` | 同一份采集写在两个函数里，只改一处会导致「界面上设了但实际下发值不一致」 |
| 三栏布局被自身断点压回单列 | `app.css` × `app.py` | 断点 1280px 而窗口宽度恰为 1280px，启动瞬间即回落单列 |

## 七、验证

本次重构配套建立了 **9 项回归门禁**（`scripts/frontend-gate/`），全部通过：

| 门禁 | 校验内容 |
|------|---------|
| 01 | 语法 + 资源引用 + CSS 配平 |
| 02 | 跨模块引用完整性 |
| 03 | DOM id 引用一致性 |
| 04 | 运行时冒烟（Node vm 同上下文加载 10 模块） |
| 05 | id 契约（含「有意变更登记制」） |
| 06 | `data-action` 契约（注册/使用双向校验，防静默失效） |
| 07 | 真实 DOM 验证（jsdom，23 项） |
| 08 | 打包产物端到端（启动 EXE 验证内置服务提供重构后资源，12 项） |
| 09 | 布局断点 × 窗口宽度 × 侧栏适配（12 项） |

门禁 07 与 09 覆盖了本次最容易出问题的两类场景：「折叠态下 `collectParams()` 是否仍能读到折叠组内的参数值」以及「响应式断点与窗口宽度的跨文件数值耦合」。

## 八、升级须知

- **安装会原地覆盖旧版本**（同一 AppId）。若程序正在运行，请先完全退出再安装
- 三栏布局需要**窗口宽度 ≥1180px**；若窗口被缩得更窄，会按设计回落为单列
- 界面资源已禁用缓存，安装后无需清理缓存即可看到新版

## 已知限制

- **CSS 视觉呈现未做自动化验证**：构建环境无可用的无头浏览器，jsdom 不实现布局引擎，上述列宽均为按规则推算的结果，实际观感以人工确认为准
- 静态 DOM 上仍有 **117 处内联事件**未迁移（本次范围限定为动态生成区域的 20 处）。分发器已就绪，可按同一模式在后续版本分批迁移
- 构建环境的 Python 需使用 `envs/default`（`build_exe.py` 通过 `sys.executable` 解析解释器）
