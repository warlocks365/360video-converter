# v3.13.6 — 元数据工具：日期来源优先级修复（探测不再覆盖用户选择）

## 问题

元数据工具中先选择「从文件名提取日期」再加入批量列表后，打开单行编辑弹窗发现日期与外部设置不一致：探测链路发现源视频自带拍摄时间时，会**无条件改写**该文件的日期来源（手动日期=源拍摄时间、「从文件名提取日期」被关闭），把用户在外面板的明确选择悄悄覆盖。

## 修复

探测的自动填充改为**尊重用户已选择的日期来源**：

- 用户已勾选「从文件名提取日期」→ 保持文件名来源，探测不再改写（弹窗与外部预览一致）；
- 用户已手动填写日期 → 保持手动值；
- 仅当用户**未选择任何来源**（未勾选文件名提取且手动框为空）时，才默认复用源视频拍摄时间（UTC 归一化本地时间的 v3.13.4 语义保留）。

需要复用源拍摄时间时仍可随时在弹窗中点击「复用拍摄时间」按钮。

## 验证

- jsdom 复用链路验证 21/21（新增 3 条日期来源优先级断言：文件名模式不被覆盖 / 无来源时复用兜底 / 手动值不被覆盖），脚本入库 `scripts/frontend-gate/_verify_meta_reuse_flows.js`；
- 门禁 01–09 全绿（07 36/36、08 12/12）。
