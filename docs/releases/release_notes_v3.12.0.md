# v3.12.0 — 前端架构重构（模块化 / 布局工作台 / 事件委托）

> 本版本为**纯前端架构重构**，不新增也不删减任何功能。所有参数项、转换模式与交互能力保持完整。后端 `app.py` 未改动。

## 本版本包含两批重构的完整成果

### 一、单文件 → 模块化（6096 行单文件 → 13 个文件）

改造前前端是单个 `static/index.html`（6096 行，含 4290 行内联 JS + 579 行内联 CSS），无法并行维护。现按职责拆分为：

```
static/index.html      1295 行   纯 DOM 骨架（零内联 JS/CSS）
static/css/app.css      612 行
static/js/00-core.js    273 行   状态 / 工具 / 统一轻提示 / 空值安全 DOM 辅助 / 事件委托分发器
static/js/10-ui.js      609 行   模式切换 / 折叠开关 / 弹窗 / tooltip / 原生对话框 / 路径字段工厂
static/js/20-map.js     525 行   地图与坐标（Leaflet / GCJ-02 转换 / 地理编码）
static/js/30-params.js  438 行   参数采集回填 / 预设 / 分辨率与码率联动
static/js/40-files.js   682 行   目录扫描 / 任务表 / 合并表 / 任务持久化
static/js/50-meta.js    645 行   元数据工具 / 三套设置区统一采集回填
static/js/60-jobs.js    852 行   任务调度（控制器 / 轮询 / 渲染器）
static/js/70-report.js  293 行   元数据报告
static/js/80-codec.js   375 行   编码器检测 / 诊断 / 日志导出
static/js/90-boot.js     51 行   启动初始化
```

拆分采用**脚本驱动的顶层语句整块切分**（函数绝不被截断），并内置 4 项无损校验：块索引分区完整、块区间连续无重叠、按块索引拼回与原脚本**逐字符一致**、写盘后逐模块重解析块集完全匹配。

### 二、任务调度重构（消除任务状态串台）

改造前 `jobId` / `pollTimer` 是裸全局单例，且 `startConversion()` 只禁用「开始转换」按钮、`startMetadataApply()` 只禁用「应用元数据」按钮——**元数据任务运行期间「开始转换」仍可点击**，新任务会覆盖 `jobId`，导致前一任务的轮询被夺走、进度永久冻结。

现已改为显式控制器：

- `ActiveJob` 控制器（`beginJob` / `endJob`）—— 检测到已有任务运行时**明确拒绝并提示**，不再静默覆盖
- 两个主按钮**同时禁用/启用**，从根上杜绝并发启动
- 单一轮询器按任务类型分派 `renderEncodeJob` / `renderMetadataJob`，每类渲染只写自己那套 DOM
- 顺带修复：VR 3D 合成原先**完全缺失按钮复位逻辑**（任务运行时不显示暂停按钮）
- 删除 274 行死代码（`pollStatus` 曾被二次覆盖赋值，原实现不可达）

### 三、单一操作栏

元数据专属操作栏与共享操作栏结构完全相同、仅 id 前缀不同，造成 10 个进度 DOM 元素重复。已合并为单一操作栏，`meta*` 进度与按钮 id 移除 12 个。每个轮询周期由「同时写两套进度 DOM（其中一套必然不可见）」变为只写一套。

主操作按钮配色原本不一致（转换用蓝、元数据用强调色），已统一。

### 四、三栏工作台布局

- `.app` 最大宽度 1200px → **1680px**
- 主体改为三栏：**左＝参数配置｜中＝工作区｜右＝实时监控（吸底 sticky）**
- 操作栏移至工作台之后并 `position: sticky; bottom: 0` **吸底常驻**
- 窄屏（≤1280px）自动回落单列

**效果**：1920px 屏横向空间利用率约 63% → **约 90%**；「开始转换」距首屏约 2500px → **0**（无需滚动）；系统资源与实时日志常驻右栏，不再随主内容滚走。

### 五、编码参数手风琴分组

`#encodeParams` 内 9 个分组全部包装为可独立折叠的分组，**默认仅折叠 2 个设备专项分组**（Okaa 双鱼眼校正、Insta360 原生文件处理，合计占面板 28%）——这两个分组只在使用对应设备拍摄时才有意义，且均为 opt-in 功能。其余 7 组保持展开，不改变既有操作习惯。

折叠使用 CSS `display:none`，**控件始终留在 DOM 中**，因此折叠状态下的参数照常参与采集，不会丢失。

### 六、事件委托（消除 XSS 攻击面）

动态生成 HTML 中的内联事件全部迁移到「`data-action` + 中央事件委托」：

- 动态生成区域的内联事件 **20 处 → 0**
- `javascript:` 伪协议链接 **1 处 → 0**
- 全局内联事件总数 **148 → 117**

**为什么这能消除 XSS 面**：`esc()` 在「JS 写在 HTML 属性里」这种上下文中并**不充分**——HTML 实体先于 JS 解码生效，`&#39;` 在 JS 解析时已还原为引号，仍可闭合字符串。改成 `data-*` 属性后，属性里不再出现函数名与引号嵌套结构，该攻击面自然消失。

顺带修正：编码器警告中 `codec` 原先未转义。

### 七、元数据设置区逻辑统一

项目有三套功能相同、id 前缀不同的元数据设置区（转换面板 `p_` / 元数据工具 `m_` / 单行编辑弹窗 `me_`）。调研发现三套**远非对称**：容器 id 用了三种不同命名法、`me_` 侧后缀为 `_opts` 而其余为 `_options`、日期总开关在 `p_` 侧是一个合并控件而在 `m_`/`me_` 侧是两个独立控件。

因此采取**只统一逻辑、不生成 DOM** 的方案（生成 DOM 会使 id 契约变成隐式的，丧失静态可校验性）：

- 新增显式 id 映射表（字段 + 容器），将来改名不会静默失效
- 统一采集 `collectMetaSettings(prefix)` / 统一回填 `applyMetaSettings(prefix, s)`
- **修复一个既有缺陷**：`m_` 侧的采集逻辑原先在两个函数里各写了一遍，只改一处会导致「界面上设了但实际下发的值不一致」——现已共用同一实现
- 统一容器显隐机制，并主动清除历史遗留的内联 `display`（原实现的 `!important` 残留会覆盖类样式导致切换失效）

### 八、路径输入统一

14 处「输入框 + 浏览按钮」的硬编码调用统一为 `data-action="open-path-dialog"` + `data-path-*` 描述目标，并新增 `renderPathField()` 工厂供后续新增入口复用。

### 九、其他修复

- **地图点击选点异常**：`reverseGeocode()` 回调中引用了未定义的变量 `lon`，导致点击地图后抛出 `ReferenceError`、逆地理编码失败。此为**改造前既有缺陷**（已与上代构建比对确认），本版本修复
- 轻提示实现由 4 套独立代码（z-index 分别为 9999/99999/100000/100001、停留时长 2500/4000/8000ms）统一为 1 套，按时长语义分档
- 消除重复实现：增量日志渲染、按钮复位、日期预览、球面模式拆分、编码器提示气泡
- 「路径输入 + 浏览按钮」等 14 处重复结构统一
- CSS 变量收口 40 处硬编码颜色
