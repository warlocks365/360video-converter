# v3.13.8 — 元数据报告：拍摄时间显示统一为本地墙钟

## 问题

元数据报告显示的拍摄时间是 ffprobe 原始 UTC 标签值（如 `2026-05-26T12:12:41.000000Z`），而元数据工具的写入/复用/源信息面板均使用本地墙钟（如 `2026-05-26 20:12:41`）——同一个 app 两处显示相差 8 小时，用户据此判定"报告时间与写入时间不一致"。

## 定位

写入链路（v3.13.4 已加固）本身时刻精确：e2e 复证 naive `15:30` → 标签 `07:30Z`（= 本地 15:30）+ FS 时间 `15:30:00`；UTC Z `12:12:41Z` → 标签精确回读 + FS `20:12:41`。偏差出在**报告的显示层**：70-report.js 三处（报告卡片"拍摄日期"行、字段值函数、文本导出）直接透传 ffprobe 原始 UTC 标签值。

## 修复

新增 `fmtCreationTimeDisplay()`（复用 50-meta.js 的 `utcToLocalNaive`），三处显示点统一转换为本地墙钟 `YYYY-MM-DD HH:MM:SS`。MP4 creation_time 标签存储的是时刻（UTC 秒），不同工具按各自时区显示——本工具全链路保证"显示 = 设定 = 标签时刻的本地表示"。

- jsdom 复用链路验证 **29/29**（新增 3 条：报告字段值=本地墙钟、空值安全、**真实产物标签核验**——v3.13.4 e2e 写入的 out_t1.mp4 标签 `07:30Z` 显示为 `15:30:00` 与写入设定一致），脚本入库 `scripts/frontend-gate/_verify_meta_reuse_flows.js`；
- 门禁 01–09 全绿（07 36/36、08 12/12）。
