# v3.13.0 — 闪烁修复 + 编码 copy 模式 + 元数据读取增强

> 自 v3.12.2 以来的变化：修复一个影响使用的闪烁问题、新增编码 copy 模式、完善元数据读取的四项能力。

---

## 一、修复：频繁弹出未知窗口的闪烁

### 排查过程（每步都有证据）

| 步骤 | 方法 | 结论 |
|------|------|------|
| ① 前端弹窗原语 | 在真实 DOM（jsdom）里运行 15 秒，给 `showToast` / `alert` / `confirm` / `window.open` 全部挂钩计数 | **全部 0 次**，控制台错误 0 条 → 排除前端高频弹窗 |
| ② 后端子进程审计 | 检查全部 `subprocess` 调用 | ffmpeg 调用全带 `CREATE_NO_WINDOW` ✓；**`sysmon.py` 有 3 处缺失**（GPU 名称检测 / nvidia-smi 探测 / nvidia-smi 采样，采样节流 1 秒一次） |
| ③ 本机复现验证 | 实测 pynvml 与 nvidia-smi 是否可用 | 均不可用 → sysmon 两条 GPU 路径都不走，非本机复现源 |
| ④ **决定性实验** | 启动打包程序，用 Win32 `EnumWindows` 每 200ms 枚举可见顶层窗口，主窗口出现后观测 20 秒（99 次采样） | **本进程零新窗口** → **闪烁不是真实窗口，是渲染层问题** |

**渲染层根因**：三栏工作台引入了两处 `position: sticky` + `box-shadow` 合成层。在**无 GPU 直通的环境（VMware 虚拟机 / RDP 远程桌面）**里，Chromium 的 DirectComposition 合成路径会出现整块区域频繁闪烁，观感即「频繁弹出未知的窗口」。

**顺带发现的真实缺陷**：Windows 上父进程无控制台且子进程未设 `CREATE_NO_WINDOW` 时，系统会为子进程**分配一个新的控制台窗口**。`sysmon.py` 的 GPU 采样节流为 1 秒一次——在装有 `nvidia-smi` 的机器上，这意味着**每秒弹出一个黑框**。

### 修复内容

1. **`sysmon.py` 补齐 3 处 `CREATE_NO_WINDOW`**（对装有 nvidia-smi 的机器是实质修复）
2. **WebView2 默认禁用 GPU 加速，改走 CPU 合成**：设置 `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--disable-gpu`（WebView2 运行时原生支持的环境变量）。本应用是表单/表格型界面，没有视频预览等重绘负载，CPU 渲染绰绰有余。**如需恢复 GPU 加速**：设置环境变量 `360VC_ENABLE_GPU=1` 后启动
3. **滚动容器加 `scrollbar-gutter: stable`**：消除滚动条出现/消失引起的布局抖动

> 若修复后仍有闪烁，请反馈**触发时机**（静止就闪 / 滚动时闪 / 启动任务后闪）与**位置**（整窗 / 某个面板），并尝试设置 `360VC_ENABLE_GPU=1` 对比——这两个信息能精确定位剩余问题。

## 二、新增：编码 copy 模式（流复制）

在编码参数面板顶部新增开关「**直接复制源流（-c copy，不重编码）**」。

- **用途**：只改封装与元数据（GSpherical 注入、faststart、拍摄时间、GPS），不做任何重编码——**零画质损失，速度接近磁盘拷贝**
- **生成的命令**：`-map 0 -c copy`，不含任何滤镜或编码器参数，但**保留全部元数据写入**
- **互斥保护**：`-c copy` 不能与任何视频滤镜共存（滤镜必须重编码）。启用后：
  - 前端把 5 个「必须重编码」的参数组（视频编码参数 / 音频编码 / 画面防抖 / Okaa 校正 / Insta360）置为**惰性**（半透明、不可交互），编码器下拉禁用，并显示提示框
  - 后端 `build_cmd` 再兜底一次：强制忽略 okaa / insv 拼接 / vidstab / 缩放，**双保险**
  - 2-pass 编码决策自动排除 copy 模式（避免把整段流复制白跑一遍）
- 支持**批量任务逐任务设置**：copy 开关随参数快照写入每个任务，可在批量模式里对单个任务单独开关

## 三、元数据读取功能增强（4 项）

### 1. moov atom 支持标注

每个媒体条目新增徽章，明确标注 moov 状态与位置：

| 徽章 | 含义 |
|------|------|
| `moov ✓ 前置`（绿） | moov 在文件头部（faststart），适合网络流播 |
| `moov ✓ 尾部`（黄） | moov 在文件尾部（录制未做 faststart） |
| `moov ✗ 缺失`（红） | 无 moov → 文件不完整或已损坏，**无法播放/转码** |

实现是**纯 Python 的 MP4 box 解析**（`probe_moov_atom`）：只读每个 box 的头字节并 seek 跳过内容，**绝不整读文件**（视频可能几十 GB）；防御损坏文件的 size<8 与非法 largesize，避免死循环。配套 **12 项单元测试**（moov 前置/尾部/缺失、size=0 到文件尾、size=1 64 位 largesize、恶意 size、MKV 头、截断文件等）全部通过。

### 2. 批量结果筛选（按源数据功能分类）

元数据报告的批量结果新增筛选栏：**一个字段下拉（用 `<optgroup>` 按六类源数据功能分组，共 18 个字段）+ 关键词输入**：

| 分类 | 字段 |
|------|------|
| 容器 | moov 状态、封装格式、文件大小、时长 |
| 视频流 | 编码器、分辨率、帧率、码率、pix_fmt |
| 音频流 | 音频编码、采样率、声道数 |
| 球面元数据 | GSpherical、pano 类型（360/180）、立体模式 |
| 时间 | creation_time |
| 位置 GPS | 经纬度、地点名称、详细地址 |

- 关键词为「包含」语义、大小写不敏感；moov / GSpherical 这类布尔字段自动切换为「全部 / 是 / 否」三态
- **纯前端过滤**（对已加载数据即时重渲染），显示「筛选后 X / 共 Y 个」

### 3. 批量结果多选 + 全选 / 反选 / 清空

- 每个条目带复选框，工具栏提供**全选 / 反选 / 清空**
- **关键语义**：全选/反选只作用于**当前筛选可见**的条目；勾选状态**按文件路径记录**（而非显示索引），因此**筛选条件变化不会丢失已勾选项**
- 实时显示「已选 N 个」

### 4. 选中的媒体加入批量转换队列

- 「加入批量转换队列（已选 N）」按钮：把选中文件按现有任务结构加入批量队列，**每个任务携带独立的参数快照**，随后**自动切换到批量转换模式**，可在批量模式里用现有的能力对单个任务单独调整参数
- 边界处理：未勾选时提示（toast，不弹原生对话框）；重复文件自动跳过并提示跳过数量

## 五、已知限制

- **CSS 视觉效果无法自动化验证**（本环境无可用无头浏览器），列宽与观感需人工确认
- `location_name` / `location_address` 两个筛选字段对大多数文件筛不出结果——报告数据来自 ffprobe tags，通常只有原始 GPS 串；文件名/地址由注入流程另存，不在 ffprobe tags 里。字段位保留以兼容已注入名称标签的文件
- 静态 DOM 上仍有 118 处存量内联事件未迁移（本次未新增任何内联事件），后续按同一分发器模式分批迁移
- 闪烁修复中的「禁用 GPU」是针对虚拟机/远程桌面环境的稳妥解；如在物理 GPU 机器上发现滚动流畅度下降，可设 `360VC_ENABLE_GPU=1` 对比
